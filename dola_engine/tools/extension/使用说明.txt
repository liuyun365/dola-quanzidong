【v1.3.2 修复】（2026-09-12）★当前版本
  问题：v1.3.1 修完后，豆包页面仍然捕获不到视频资源（面板显示"未提取到资源"）。
  原因：对照主程序（豆包正常）的实现，发现插件的"获取方式"多了 4 道主程序没有的限制——
        ① fallback_api 域名白名单：插件只允许 doubao.com / byteintlapi.com，
           主程序 LocalVideoResolver.BuildRequestUri 完全不限制域名。豆包一旦把
           fallback_api 指到 CDN 域，URL 就在 addFallbackApi 里被静默丢弃。
        ② 强制 https：插件要求 https，主程序 http/https 都收。
        ③ 正则缺"多层转义"：主程序 FallbackApiStreamScanner 用 3 条正则覆盖
           0/1/2 层 JSON 转义，插件只有 2 条。豆包 chain 把 JSON 再套一层字符串时漏掉。
        ④ 扩展可访问域过窄：host_permissions 只有 5 个域，fallback_api 在别的域时
           连 fetch 都会被 CORS 拦掉。
  修复：① 移除 fallback_api 域名白名单（与主程序一致：合法 http/https 即可）；
        ② 放开 http 协议限制；
        ③ 转义正则合并为一条通用式 /fallback_api\\*"\s*:\s*\\*"(.+?)\\*"/g，覆盖任意层数；
        ④ host_permissions 改为 *://*/*（只影响扩展自身发起的请求，
           content_scripts 注入范围不变）；
        ⑤ 全链路诊断日志（见下），以后"抓不到"能一眼定位。
  影响：Dola/千问/云雀 行为不变（已验证 13 项单测全通过）。

【怎么用日志定位问题】
  打开 chrome://extensions → 找到本插件 → 点【Service Worker / 检查视图】
  → Console 标签，去页面生成一次资源，会看到一行：
    [哆啦助手] doubao 提取诊断: body=xxxB | image(json)=x image(regex)=x
             | fallback_api出现=x 候选=x 首个主机=xxx | 视频成功=x | items=x
  · body=0            → 响应体没拿到
  · fallback_api出现=0 → 平台响应里压根没有 fallback_api（接口改版）
  · 候选=0 但出现>0    → URL 格式不对（把"首个主机"发给开发者）
  · 候选>0 视频成功=0  → 请求或解码失败（看后面 fallback_api failed / main_url 解码失败）

【本机加载测试（Chrome / Edge）】
  方式一（zip 直装，推荐）：
    打开 chrome://extensions（Edge 为 edge://extensions）→ 打开【开发者模式】
    → 把本 zip 文件直接拖进页面即可（注意：zip 根目录必须直接是 manifest.json，
      本包已按此结构打包，不要再套一层文件夹）
  方式二（文件夹加载）：
    1. 解压本 zip 得到文件夹
    2. chrome://extensions → 打开【开发者模式】
    3. 点【加载已解压的扩展程序】，选择解压出的文件夹
  4. 浏览器工具栏出现紫色"哆啦助手"图标即成功

【使用】
  · 打开豆包/千问/Dola/云雀 页面，右下角出现哆啦助手浮动面板
  · 30 秒开关（面板内紫色开关）：在豆包/Dola 视频生成页开启，
    生成时自动按 30 秒输出（Seedance 2.5）
  · 页面出现图片/视频资源时，面板自动列出，点"下载"即得无水印原图/视频
